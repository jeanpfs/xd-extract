# Changelog

## Unreleased

- The width of left-aligned text (which XD does not store) is estimated from Helvetica advance widths instead of a flat 0.6 em per character: within about 1-3 % of Arial and Helvetica rendered by resvg for regular text, up to 8 % for bold, against about 30 % too wide before. A line of area text is capped at its frame width. Frames that used to leave an empty margin to the right of text now fit. XD's `visualBounds` turned out to be stored only on text that has a shadow or blur, in another coordinate space, so it cannot replace the estimate.

## 0.2.0 (2026-10-13)

- Inside and outside stroke alignment on closed shapes (rect, ellipse, closed paths): the stroke is drawn at twice the width and clipped to the shape (inside) or masked out of it (outside). The frame no longer includes the outer half of an inside stroke and now includes the full width of an outside one. `stroke-align-ignored:*` is now reported only for lines, open paths and unknown values, and no longer when there is no stroke (XD stores `align` on `stroke: none`). `report.clips` still counts mask-group clips only.
- Drop shadows (`style.filters` `dropShadow`, `global: true`) on shapes and groups become an SVG `<filter>` (blur `stdDeviation` = XD `r` / 2, offset, colour and alpha, several shadows stacked below the art). A group's filter wraps its mask clip so the shadow is not clipped. Content frames grow to the visible shadow (`r` beyond the offset box); a plate frame includes the plate's own shadow only. Other filters are now `unsupported-style:filters:<type>`, and a drop shadow that is not `global: true` is `unsupported-style:filters:dropShadow-local`. The `r / 2` blur mapping is from convention, not verified against Adobe's own export. In the only public file with shadows, all five are on text nodes, which are still skipped, so the real-data check is private only.
- Text: `text` nodes become live `<text>` with one `<tspan>` per line XD laid out (baseline origin, XD's own wrapping), per-range font family, weight (from the style name), italic, size and ARGB colour, and left, centre and right alignment (centre and right text is anchored at the origin so a substitute font stays aligned). The frame includes text: exact for centre and right (XD stores the width in `x`), estimated at 0.6 em per character for left-aligned lines (`text-bbox-approximate`). Fonts are not embedded (`text-font-not-embedded:<family>`). Not converted and reported: text frames other than `positioned`, justified text, a stroke on text, a non-zero `charSpacing` (read as 1/1000 em, unverified). Whitespace-only text is dropped without a warning. A node that still has no readable layout stays `skipped-text`.
- Found by surveying 76 public `.xd` files after the text work shipped, and fixed: filters with `visible: false` (XD keeps disabled effects in the file, about 6,000 in the survey) are ignored instead of being drawn as shadows; `area` and `autoHeight` text frames (about 2,500 nodes) are anchored on the frame width (their `x` is an offset inside the frame), with an exact box; `textTransform` (uppercase, lowercase, titlecase) is applied; underline and strikethrough become `text-decoration`; superscript and subscript are reported as `text-script-unsupported:*`. Each text line now carries its own anchor, so `text-anchor` is emitted on the `<tspan>`.
- Validation: text counts as shapes, `<tspan>` must carry a fill, and text is removed before the raster checks (fonts are never loaded); `text-not-rasterized` says so.
- `xd redact` keeps `rawText` as `x` per character (line breaks included), plus `fontStyle` and `paragraphAlign`, so redacted documents still lay text out. The public fixture was regenerated; this changes every golden that contains text.
- Two more public fixtures, anonymised and pinned by commit and sha256 in `scripts/fixtures.mjs`: Adobe's XD-to-Flutter test suite (BSD-2-Clause; all gradient types, blend modes, polygons, repeat grids, symbols, blur, shadows, area text) and its example app. `pnpm fixtures:build` redacts all of them. `xd redact` also keeps `textTransform` and `textScript`.
- Shadow frames follow the visible shadow: the reach of a blur is where its Gaussian edge drops below about 6 % alpha (a faint shadow adds no margin), instead of the full radius. The filter region still covers 3 sigma.
- Validation: when an SVG contains text, `edge-band-drift` and `tight-frame` are skipped (text is not rasterized, so an edge can look empty only because of what was left out).
- Symbol instances: a `syncRef` node now takes its content from the node whose id it names (`syncSourceGuid`), with its own transform and the children it overrides (unchanged children are placeholders). Masters are found on every artboard and in the new `resources` document (`XdDocument.resources`), where XD keeps `meta.ux.symbols`. An instance whose master cannot be found stays `unsupported-node:syncRef`.
- The resources AGC (`resources/graphics/graphicContent.agc`) is now read from `.xd` files and fetched for share links (a miss is not an error; a refused token is `TokenExpired`). `xd redact` keeps only what the converter reads from it (symbols, gradients, clip paths), and gives `syncSourceGuid`, `guid` and the keys of `gradients` and `clipPaths` the same tokens as the ids they refer to.
- Polygons (`shape.type: polygon`, with `points`) become closed paths and take inside and outside strokes.
- Blend modes (`style.blendMode`) become `mix-blend-mode` on shapes, groups and text. `normal` and `pass-through` draw as usual; an unknown mode is `unsupported-style:blendMode:<mode>`. `blend-mode-backdrop` reminds that the backdrop is only what is exported.
- `edge-band-drift` now needs an edge band with essentially nothing in it (under 0.3 %, was 2 %): a triangle's apex or a circle's top is not mask drift.
- Gradients: linear and radial gradients become `<linearGradient>` and `<radialGradient>` (bounding-box or user-space units as XD stores them, the radial focus and its own transform, stop alpha as `stop-opacity`), on fills and strokes, shared between identical uses. Stops come inline (`gradient.meta.ux.gradientResources`) or by `ref` from the resources document, which is how XD writes shared gradients. A single stop is a plain colour; a bounding-box gradient on a shape with no width or height uses its first stop (`gradient-degenerate-bbox`). Angular gradients have no SVG form and stay `unsupported-fill:gradient-angular`; a gradient on text stays `unsupported-fill:gradient`. `xd redact` keeps the `units` enum.
- Validation: `dangling-reference` (error) when a `url(#id)` points at an id that does not exist.
- Object blur (`uxdesign#blur`, not background): an `feGaussianBlur` whose standard deviation is XD's blur amount (assumed; two blurs add in variance), inside the same filter as the node's drop shadows (which then shadow the blurred object). The frame grows by the visible reach (about 1.5 sigma). A background blur, a non-global blur and an unreadable one are reported (`unsupported-style:filters:uxdesign#blur-background|-local`).
- Image fills: a `pattern` fill becomes an SVG `<pattern>` over the shape's bounding box with the picture embedded as a data URI (`cover` crops to fill, `fill` stretches). The bytes come from the `.xd` (`resources/<uid>`, only the pictures a fill uses are inflated) or are fetched for a share link (their components are listed in the manifest; a miss does not fail the load, a refused token is `TokenExpired`). The type is read from the first bytes (PNG, JPEG, GIF, WebP), and a picture over `--max-embed-bytes` (default 2 MiB) stays `unsupported-fill:pattern-too-large`. A moved or zoomed fill (`offsetX`, `offsetY`, `scale`) is drawn at the default and reported (`pattern-offset-ignored`): its formula was never verified. Images on strokes and on text, and an unknown scale behaviour, are reported.
- `--record` writes images as base64 and replays them byte for byte.
- `xd redact` drops pictures; `--keep-images` keeps them under anonymised ids and `--drop-image <uid>` leaves one out. `uid` and `scaleBehavior` survive anonymisation. The `tests-suite` fixture keeps Adobe's numbered test tiles, not the Glyphicons Pro icon it also contains.
- `xd --version` / `-v`.
- Release workflow: a `v*` tag publishes to npm with provenance and creates the GitHub release from this file.
- Docs: `docs/reference.md` (errors, warnings, validation findings, file formats, troubleshooting), `CONTRIBUTING.md`, `SECURITY.md`, issue and PR templates.

## 0.1.1 (2026-10-05)

- Fix: a top-level node that is a single shape (rect, path, ellipse...) was drawn outside its own `viewBox` whenever the shape carried a translate, which gave an empty or half-empty SVG. The frame is measured in the root's own coordinates, so the root's transform is now ignored for shapes too, as it already was for groups. Found on a real share link (6 of 13 single-shape roots); `xd validate` reported it as `render-empty` or `edge-band-drift`.
- Verified on a real share link that carries vector data (6 artboards, 120 top-level nodes, XD 2.33, AGC 1.5.0): the page, the manifest and every AGC were fetched on the first try. The manifest URL was in the static HTML, and the AGC revision is the component's own `version`.

## 0.1.0 (2026-10-05)

- `xd inventory`, `xd extract`, `xd validate`, `xd redact` (with `--exclude <node>` to drop top-level nodes before anonymising).
- Sources: Adobe XD share link (pure HTTP, optional `--browser` fallback) and `.xd` files.
- AGC to SVG: groups, rect (with corner radii), path (evenodd), compound, line, circle, ellipse, solid fills and strokes, mask groups to `clipPath`, frame by plate or content box, mask-drift snap.
- Reported, not converted: gradient and pattern fills, shadows and blur, text, inside-aligned strokes.
- Validation: static lint and resvg raster checks.
- Skills: `xd-extract-svg`, `xd-inventory`, `xd-validate-svg`.
- The CLI exits quietly when its output pipe is closed early (`xd inventory ... | head`).
